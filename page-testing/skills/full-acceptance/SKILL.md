## 做什么

启动本插件自带的 full-acceptance 工作流，对有源码的项目做全自动验收循环。你的职责是正确启动它并转述结果，不要自己编排测试或替它修代码。

## 步骤

1. 若 dynamic-workflows 技能尚未加载，先用 Skill 工具加载它（CreateWorkflow 的 path 方式依赖它）。
2. 从用户话里取两个参数：
   - `target`（必填）：被测项目源码根目录的绝对路径；用户只说了项目名就先问清路径再启动。
   - `scope`（可选）：测试范围一句话（如「登录和下单流程」）。用户没划范围就不传，由工作流全自定；只在用户明确划了范围时才传。
3. 用 CreateWorkflow 启动：`path` = 本技能基目录下的 `full-acceptance.dwf.ts`，`args` = { target, ...(用户划了范围则加 scope) }，`name` = 「全流程验收」。
4. 等运行完成通知（不要轮询），向用户转述最终结论：共发现多少问题、复测通过多少、残留多少、完整报告在 `<项目根>/qa-report.md`。

## 如实说明（用户问到再说）

- 工作流会修改被测项目源码并做本地 git commit（不 push）；项目不是 git 仓库时只改文件不提交。
- 本机没装 adb 时安卓线自动整线跳过并写进报告的未覆盖项，属预期行为。
- 启动时 ZCode 会弹工作流确认窗（含阶段图），用户确认后才开跑。
