# audit 分支协议 — 找 bug（验证已有功能对不对）

你在扫描一个页面（任务流模式除外，见文末「任务流」）。以下维度逐项过，只描述问题，不给修复方案。
（严重度定义见 scan-protocol.md 返回格式一节。）

**目录**：维度 1 操作顺畅 / 维度 2 稳定可靠 / 维度 3 流畅敏捷 / 维度 4 筛选搜索正确性（硬协议）/ 维度 5 内容正确性 / 维度 6 权限与角色 / 维度 7 深度使用与状态矩阵 / 任务流（跨页，单独派单时执行）

## 维度 1：操作顺畅 — "我想做的事能做成吗？"

- **链接有效性**：所有内部链接 fetch 检查状态码，404/500 记入
- **死链接检测**：见 DOM 级自动扫描第 2 条（# / javascript:void(0) / 空按钮），结果并入本维度
- **表单测试**：空提交 → 错误数据 → 合法数据 → 检查反馈是否正确
- **交互组件**：弹窗/下拉/折叠面板/标签页，展开→快照→收起→检查状态切换；若同时检查遮挡或布局，再附特写截图
- **键盘导航**：按 Tab 键是否能按合理顺序走完所有可交互元素
- **操作反馈**：点击按钮是否有视觉反馈（hover 变色、点击波纹、按钮下沉），点完有没有"正在加载"的提示
- **交互元素全覆盖**：见 DOM 级自动扫描第 10 条，确保不在已知流程里的可交互元素也测到
- **特殊控件专项**：日期选择器（能否直接弹出日历）、文件上传（选文件→进度→结果）、下拉多选（多选/清空）、富文本（输入/加粗/传图）、拖拽/悬停/双击——每种至少真实操作一次
- **导出专项（每个导出按钮必走完整链路）**：点击导出 → 等待下载 → 打开文件核对：① 表头语言与页面语言一致 ② 无乱码 ③ 数据行数与页面统计数一致 ④ 字段完整（无大片空列）⑤ 导出内容符合当前筛选条件 ⑥ 导出成功反馈与真实下载一致（提示"导出成功"但无文件 = P0）⑦ 单元格值抽查与页面一致（组织范围、状态等字段不得是内部代号/占位文本）。跳转行为要一致（同类导出有的跳下载中心有的不跳 = 记不一致）
- **导入专项**：下载模板 → 按模板填已知数据（含边界值）→ 导入 → 验证数据出现在页面且可被搜索到；导入失败的报错是否可读、是否指明行号
- **跨页全选语义**：列表点"全选"后执行操作（导出/删除/分配），验证作用于**全部数据**而非仅本页；"选择上一级"时下一级应联动勾选

## 维度 2：稳定可靠 — "用起来稳吗？出错了有提示吗？"

- **JS 异常**：注入 console.error 拦截器 → reload → 操作 → 收集异常
- **控制台警告**：见 DOM 级自动扫描第 8 条，同时收集 console.warn（CSP 违规、弃用 API 等），结果并入本维度
- **CSP 响应头**：见 DOM 级自动扫描第 9 条，检查是否缺少 blob:/data: 等指令
- **网络请求失败**：4xx/5xx 响应标记
- **资源加载完整性**：记录页面全部 JS/CSS/图片加载结果（成功/404/500/超时），包括交互后新触发的请求；页面可用但某资源 404（如静态路径未代理）= P1，标注资源 URL
- **加载态**：操作后是否有 loading 指示器，还是页面静止让你干等
- **空态**：数据为空时页面是否正常显示，不崩溃、不报错
- **错误态**：API 请求失败时，是否有友好的错误提示，还是直接白屏或报裸错
- **数据安全感**：密码输入是否有显隐切换；登出是否确认；敏感操作（删除/修改/支付）是否有确认步骤
- **防抖/防重复**：快速连续点击提交按钮，是否会重复提交
- **间歇故障采样**：核心操作（提交/加载/跳转）第一次结果为"正常"时，**重复执行一次**核对；两次结果不一致 → 记「间歇性故障」P1。「有时候报503」「第一次点击没反应第二次才有」这类 bug 只有重复采样才能抓到，单轮通过 ≠ 稳定

## 维度 3：流畅敏捷 — "打开快吗？用起来卡吗？"

- **加载感知**：页面加载完成时间（< 1s 快，1-3s 一般，> 3s 慢）
- **LCP**：最大内容绘制时间，记录并评估
- **CLS**：累计布局偏移，记录并评估（滚动到底后采样）
- **大图检测**：自然宽高远超视口尺寸的图片，是否未做压缩/懒加载
- **滚动流畅度**：长列表页面滚动是否卡顿
- **首屏优先级**：首屏内容是否优先加载，非首屏资源是否延迟加载

## 维度 4：筛选/搜索正确性（硬协议，逐字段执行，不允许抽查）

1. 用 setup 写入的已知测试数据做断言基准（数据值是自己写的，结果对不对有唯一标准答案）
2. 每个筛选/搜索字段输入一个已知值 → 断言返回结果**每一条**都匹配该条件（无误报）
3. 断言已知匹配的数据**全部**出现在结果中（无漏报）
4. 数值类筛选验证边界：输入 2，结果中不得出现 1 或 3；输入 0 只出 0
5. 多条件组合筛选 + 筛选后翻页，条件是否保持
6. 空条件搜索：默认结果数与不加筛选时一致（不筛选反而数据更少 = 记 P1）
7. 筛选后总数变化：筛选前 N 条，筛选后应 ≤ N 且与"符合该值的已知数据条数"一致

任一步失败 → 记「筛选不生效/筛选结果错误」P1；统计数与列表实际内容矛盾 → P0。

## 维度 5：内容正确性 — "结果对不对？全不全？"

- **应有性**：每个结果区（列表/推荐/详情/搜索/统计）先回答"按项目画像和项目自身文档，这里应该有什么？"——依据永远来自项目自身，不来自预设，缺项记「内容缺失」
- **空结果核查**：页面显示无结果时，直接查数据源（接口/存储）——数据源有而页面空 = P0
- **数据源比对**：字段值、数量、状态与接口返回抽查比对，不一致记「数据错乱」
- **重复条目**：同实体多条（同关键字段/同名），记「数据重复」，附两条内容
- **生成类内容**（项目含 AI/聚合生成时）：按项目文档定义的输出结构核对完整性，缺结构记一条
- **字段间矛盾**：列表逐行扫描同一记录内字段逻辑矛盾——已过期但仍在线/可用；已删除/已离职但仍出现在选择列表；提示成功但数据未变化；勾选"包含下级"保存后回显未勾选
- **本页统计数字**：把本页所有统计数字（指标名+值）放进返回的 findings，跨页对账由主 agent 做

## 维度 6：权限与角色 — "每个人看到的都一样吗？"

- **角色可见性**：按派单下发的凭据逐角色核对「应见/不应见」（依据项目角色定义，不预设）
- **越权访问**：低权限直接输入高权限 URL，未拦截（403/重定向/无入口）= P0
- **权限名可读性**：UI 出现技术代号（admin/role_3 类）而非项目规定的可读名，记「可读性缺失」
- **异常操作走查**：自删/自禁/改自己权限/删他人数据/越权修改——每个实点一次并记录结果
- **不可见即不可达**：UI 隐藏 ≠ 权限生效，必须用直接 URL 验证
- **权限配置生效闭环**：给角色配置权限（如勾选某个子菜单）→ 保存 → 用该角色账号登录 → 验证实际可见范围 = 配置值。配 A 得 B、保存后不生效、权限最大的人反而无权限，逐条记 P0/P1
- **业务设置生效闭环**：改一个业务设置（必填开关、某个业务开关、启用/停用规则）→ 到它**影响的下游页面**验证联动生效（设必填后表单是否有必填标记、停用后编辑入口是否锁定、开启后选项是否出现）
- **跨账号投递验证**：「通知/分配/分享/转交」类操作执行后，切换到**接收方账号**验证可见/可收到（发送方提示成功 ≠ 接收方到达）；评论/动态类内容验证对目标人群的实际可见性

## 维度 7：深度使用与状态矩阵（"每个功能真的用过一遍"）

- **清单来自代码，不来自肉眼**：测一个域之前，先从代码枚举它的子功能（grep 按钮 id/事件绑定/端点/state 分支/页面渲染点），派单 prompt 内联这份清单+边界样本（空/非法/超大/越界），agent 照单执行——清单上没有的项不算漏测算没枚举到。
- **一代理一功能不大于一域**：域拆成功能级派单（同一功能在多页渲染的，逐页各一条断言），注意力稀释是执行不彻底的直接原因。
- **状态矩阵**：每个核心功能先枚举其数据状态（如诊断：澄清中/流式中/完成/失败/刷新恢复；工单：待处理/已处理；导入：排队/进行中/完成/失败），每个状态至少真实跑一次并断言 UI 表现——只在"有数据"的默认态测过的功能不算测过
- **同屏对账（扩展维度 5）**：任何「计数 UI」（进度条 N、徽章数、badge、已完成/进行中计数）必须与同屏实体列表行数/实际个数对账，不只限列表和统计卡——同一屏出现两个口径不一致的数字即为 bug
- **流式/时序断言**：凡有流式/轮询/动画进度的功能，必须抓中间态断言（计数单调、进行中非零、帧字段一致），终态正确 ≠ 时序正确
- **能力质量抽测**：AI 类功能（诊断/识别/搜索/生成）必须用真实正向用例断言**结果内容质量**——如上传真实故障照片→断言回答正确说出图中设备与症状；HTTP 200 ≠ 功能正确
- **越界样本**：测 AI 类功能必须带一个"不应答"的负向样本（非支持领域/无关内容/乱码），断言被拒答或明确声明边界——有问必答=幻觉放大器（事故教训：对不支持的品牌仍产出完整假报告）
- **响应变化断言**：同一输入跑两遍（或改词再问），断言 AI 文案/结果**有实质差异**——逐字相同=代码在跑静态兜底模板而非真推理（事故教训：追问多轮一字不差，根因=提示词渲染报错被静默兜底）
- **写库对账（后端验证）**：凡"提交后沉淀数据"的功能，必须用接口/DB 复核数据真落库且能被下游消费——UI 绿 ≠ 数据链路通（事故教训：页面提示成功，但数据没落库或落库后下游检索不到）

## 任务流（仅此节单独派单时执行——你是唯一跨页的子代理）

人不是顺着清单用产品的。以「用户任务」为主线（prompt 会给你任务清单），台账只作兜底防漏。

**你的实例是贯穿多页的**：主代理给你一个独占实例走完全部任务，你不关闭它、不切换实例；每跨一页前确认仍在同一实例。实例约束与单页扫描相同（见 scan-protocol.md）。

- 一次执行一个任务，从首页自然入口开始，走真实用户路径，记录每一步快照；涉及视觉布局、遮挡或裁切时再截图
- **每个任务绑定一个用户视角**：操作前，先写一句「作为这个用户，我预期点这里会发生什么」；操作后对照现实：符合预期 / 不符合（差异即问题）/ 出人意料（可能是亮点或设计缺陷）
- **自然路径优先**：任务中遇到的新入口、弹出内容，跟着用户好奇心走，不必先回台账——台账的动态 diff 会在之后补上遗漏项
- **核心流程**：登录/注册/搜索/发布/下单，完整走一遍
- **步骤计数**：完成一个核心任务需要多少步，记入 findings
- 任务经过的页面各自清台账：零 pending 才算该任务完成
- **任务清单即功能闭环清单**：每完成一个任务标 `verified`（附走过的页面），做不完标 `skipped` + 类型化原因；全部处置完才算任务流完成
- **子功能枚举**：每个任务拆到子功能级（如「上传并解析一个文件」拆：选择文件/拖拽上传/超大文件/错误格式/解析失败重试），逐项标 tested/未测——功能级通过但子功能漏测 = 任务未完成
