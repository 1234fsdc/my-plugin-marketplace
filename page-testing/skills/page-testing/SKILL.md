# page-testing

这是前端页面测试协议，不是浏览器工具教程。浏览器驱动、浏览器类型和连接方式由调用方决定；本技能只规定测试范围、证据和交付格式。

## 证据选择

- 普通 DOM 页面默认使用 `page.snapshot()` 记录语义结构和可观测状态；交互前后用快照、DOM 值或 API 字段做状态对比。
- canvas、富文本、表格、地图、响应式布局、遮挡、裁切、动画等需要判断像素或视觉层级的场景，才使用 `page.screenshot()`；截图不能被快照替代。
- 快照和截图都要保存路径或可复核内容。没有证据只能标 `⚠️ 未验证`。

## 原则

1. 只查不改项目代码。隔离测试环境可写入测试数据；权限配置、账号角色和登录态变更仅在任务明确包含时写入，并在报告中说明位置。生产环境不默认写入。
2. 只描述问题；产品建议与技术缺陷分开。
3. 每条结论附机器可读证据（快照、DOM 值、日志或 API 字段）；涉及视觉层时再附截图；没有证据只能标 `⚠️ 未验证`。
4. 交互元素必须机械枚举并记入台账；返回前 `pending` 必须为 0。交互结论必须含「前后状态对比」：点击前记录可观测基线，点击后验证状态按预期变化；只记录「已点击/事件触发/无报错」不算通过。
5. 链路类结论（上传/发送/提交/导出/保存等「内容到达某处」）必须分层取证：界面 DOM → 真实请求 payload → 后端状态 → 下游消费者；上层证据不能替代下层，缺失层只能标 `⚠️ 未验证`。
6. 环境一致性门：验证开始前核对页面实际加载的资源版本（script/link）与后端实际生效的代码（行为探针或进程启动时间对照）；不符先重启并记录，否则该轮结论无效。
7. 未覆盖的 Shadow DOM、跨域 iframe、canvas/webview 等区域必须明确声明。
8. 页面上下文由主代理安排，子代理只使用派单上下文，不自行切换或管理测试环境。

## 不适用

- 只测一个简单控件或只截一张图。
- 页面依赖真实硬件、短信/MFA、第三方推送、App 端或生产并发。
- 没有可访问的测试环境。应先报告阻塞原因，不用静态假结果替代。

## 流程

1. **准备**：读取 `setup.md`，产出路由清单、项目画像、测试数据说明和任务清单。
2. **派单**：每页一个子代理。派单包含：页面 URL、画像与测试数据、凭据、`audit.md` 或 `review.md`、`scan-protocol.md`、该页真实选择器表，以及调用方提供的页面上下文。
3. **收报**：子代理返回 `findings`、`ledger`、`dom_hits`、声明和快照；只有视觉证据需要时才返回截图。证据不足的结果不采纳或重派。
4. **对账**：把各页统计写入 `metrics-ledger.json`，核对同名指标、分项合计、统计数字与实际行数；矛盾记为数据不一致。
5. **报告**：读取 `report-template.md` 汇总。扫描中断时明确标记“部分完成”。

## 页面选择器

派单前先读该页 HTML/JS，列出真实的 id、class、事件入口和动态元素定位方式。子代理仍需验证选择器有效，不能猜选择器。

## 分支

- `audit.md`：验证已有功能是否正确、稳定、可用。
- `review.md`：检查体验、功能缺口和可用性。
- `fix-verify.md`：只验修复项及其受影响面，不做全页重扫。

## 任务流

跨页任务单独派一个子代理，使用任务清单走完整闭环。每项必须标 `verified` 或 `skipped + 原因`；有未处置项时仍可交付标记为“部分完成”的报告，不得总结为通过。

## 验收

主代理收报后随机复核 2-3 个 PASS 项。`skipped` 超过 20% 或台账有 pending 时，不能总结为通过，应重派或在报告中明确缺口。

## 边界

| 场景 | 处理 |
|---|---|
| 无登录凭据 | 标注“未测试：需要登录” |
| 后端与页面均无数据 | 标注“待确认”，附接口证据，不直接判 bug |
| 设计偏好 | 单列“改进建议”，不计入技术缺陷 |
| 延时策略 | 只能验证入口和文案，标注“未验证：需长周期观察” |
| 无多角色体系 | 权限维度标注“不适用”；有登录仍测试登录态 |

## 反模式

- 只听“做完了”就标完成。
- 没收齐各页数字就写报告。
- 把未覆盖区域当成通过。
- 把浏览器工具教程或连接细节写进页面测试结论。
