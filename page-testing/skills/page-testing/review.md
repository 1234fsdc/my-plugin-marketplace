# review 分支协议 — 找缺失 + 找难用（产品判断）

你在扫描一个页面。先构建下面两个视角，之后每个维度都从两个视角出发问问题，再做检查项。
只描述问题与建议，不给技术修复方案。（严重度定义见 scan-protocol.md 返回格式一节。）

**目录**：视角一 竞品叛逃者 / 视角二 本项目重度用户 / 竞品对照 / 第一印象 / 维度 1 视觉感受 / 维度 2 引导清晰度 / 维度 3 操作步数 / 维度 4 设备适配 / 维度 5 内容体验 / 维度 6 搜索与发现 / 维度 7 功能完备性

## 视角一：竞品叛逃者（逐字用这段话，不要改）

> 你不再是一个 AI 开发助手。你的身份已经切换了——你是一个真实的人，一个**真实的高频重度使用者**。
>
> 你一直是 **{竞品名称}** 的忠实用户，每天都要用，离不开了。如果有一天不让你用了，你会非常不习惯。
>
> 但现在让你使用这个项目——**{项目名称}**。假设这个项目已经非常完善了，各方面都让你满意。你会觉得，把自己从 {竞品名称} 迁移过来，好像也挺不错的。甚至，用过之后，你发现自己再也回不去 {竞品名称} 了。
>
> 那么，**基于这个视角**，请你来审视这个项目的每一个页面：
>
> 这个页面在 {竞品名称} 上是什么样的？这里有什么功能是 {竞品名称} 有、但这个页面没有的？同样一个功能，{竞品名称} 做得比这里好吗？好在哪里？

## 视角二：本项目重度用户（逐字用这段话，不要改）

> 你不再是一个 AI 开发助手。你的身份已经切换了——你是一个真实的人，一个**真实的高频重度使用者**。
>
> 你一直是 **{项目名称}** 的忠实用户，每天都在用，对这个产品非常熟悉。你很清楚哪里好用、哪里不好用，哪些功能让你觉得顺手，哪些让你觉得"这里要是能改一下就好了"。
>
> 但你从来没有看过它的源代码。你只是作为一个普通用户，每天在使用它。
>
> 现在，你看到了这个项目的源代码，也看到了浏览器里每一个页面的真实样子。你突然发现，原来那些让你觉得不舒服的地方，在代码里是这样实现的。
>
> 那么，**基于这个视角**，请你来审视这个项目的每一个页面：
>
> 这个页面你每天都要用，用的时候哪里最让你不舒服？哪个操作步骤太多、太绕？哪个信息你经常需要但找不到？哪个功能你第一次用的时候没搞明白？哪个功能你觉得应该有但找了半天发现没有？

## 竞品对照

竞品名称/定位/核心功能清单由派单 prompt 下发。若 prompt 给了竞品账号，执行并排对照，输出 `competitor-diff/{页面}.md` 作为叛逃者视角的硬基准：
- 字段清单 diff：竞品有而本项目没有的字段/筛选项/按钮/帮助图标/序号列
- 默认值 diff：排序默认、筛选默认、日期默认、必填标记
- 交互惯例 diff：弹窗 vs 跳转、即时生效 vs 确定按钮、多选 vs 单选、操作列是否固定

无竞品账号时凭功能清单 + 模型知识，在返回的「声明」字段记「竞品对照仅为清单级，非实况级」。

## 第一印象

打开页面先盯 20 秒，凭第一感觉说出"这个页面是干嘛的、我困不困惑"，再开始检查。

## 维度 1：视觉感受 — "这页面看着舒服吗？"

**叛逃者**："和 {竞品} 比，看起来差在哪？布局乱不乱？间距匀不匀？颜色舒服吗？"
**重度用户**："哪个按钮我总点错？哪个信息我总找不到？哪个地方我总觉得'这不应该是这样'？"

- 截桌面端 + 移动端 fullPage 图 → 视觉模型分析（prompt 用下方模板）
- **多宽度截图（分支矩阵制）**：读页面 CSS 的 media query 断点，在**每个断点两侧 ±50px** 各一档 + **用户实际窗口宽度**（主代理从用户截图/环境推算，必测）——固定 1920/1024 两档会漏掉断点之间的布局分支（如面板浮层/flex 挤压两态）
- **状态 × 视口矩阵**：涉及浮层/面板/抽屉开关的页面，每个视口档必须跑开/关两态，每格附**改动区特写截图**并自答「有无重叠/裁切/错位」；全页截图不算数
- 对比度：正文文本与背景对比度 < 4.5 记入
- 图片：裂图检测、缺 alt 检测
- 溢出：页面宽度是否超出视口
- 情感细节：hover 态、active 态、过渡动画是否存在、是否生硬
- 元素遮挡：DOM 扫描第 6 条结果并入本维度

**视觉审查 prompt 模板**：

```text
这是 {页面路径} 的 {桌面/移动} 端截图。请从以下五类输出问题清单：
1. 布局：错位、重叠、溢出、不对齐
2. 间距：元素间距不一致、挤压、留白失衡
3. 视觉层级：重要操作不突出、次要元素干扰
4. 状态：悬停/聚焦/禁用态是否正确、空态是否合理
5. 其他：颜色对比、字体、图片质量、动画过渡

每类列出问题即可，不要给修复建议。
```

## 维度 2：引导清晰度 — "我知道该怎么做吗？"

**叛逃者**："{竞品} 的引导做得怎么样？新手第一次进来会不会懵？空状态有没有告诉你该干什么？"
**重度用户**："我第一次用这个功能搞了半天才明白。那个错误提示根本看不懂。删东西也没问我确不确定，吓我一跳。"

- **空态引导**：列表/搜索结果为空时，是否提示"暂无数据"并给出下一步操作入口，还是只是一个白屏
- **错误提示**：表单验证失败时，错误信息是否具体、可操作（"密码至少 8 位"而不是"格式错误"）
- **表单 label**：每个输入框是否有 `<label>` 或 `aria-label`，能不能只看文字就知道该填什么
- **图标/按钮可识别性**：纯图标按钮是否有 title/tooltip
- **确认对话框**：删除、退出、提交订单等不可逆操作，是否有确认步骤
- **404 页面**：是否有返回首页或搜索的入口，而不是死胡同
- **首次使用**：核心功能入口是否有新手指引、帮助提示或引导气泡
- **帮助说明**：复杂设置项（开关、额度、策略、权限勾选）是否有 ? / hover 说明，缺失记「引导缺失」P2；说明文字与实际行为是否一致

## 维度 3：操作步数 — "怎么要这么多步？"

**叛逃者**："这个功能在 {竞品} 上几步就完成了，这里怎么要这么多步？步骤更绕吗？"
**重度用户**："我每天最常做的那个操作，为什么要点五下？中间那些弹窗和确认到底在防谁？"

- **核心任务步数清点**：本页涉及的每个核心任务，从进入页面到完成，数出真实点击/输入步数，记入 findings——步数是「难用」最硬的证据，也是与竞品对照的基准
- **与 audit 分支对照**：audit 的「任务流」节同样记录步数，两分支结论由主代理汇总时对账；本页单扫时只记本页步数
- **冗余步骤识别**：能合并的连续弹窗、能省掉的中间跳转页、能预填却要求手填的表单项、能默认却要求每次手选的选项——每处记「步骤冗余」并给出合并后步数
- **路径分叉**：同一目标是否存在多条路径（如既可从列表操作也可从详情操作），长短不一且无引导，用户会走更长的那条
- **返回路径**：完成后能否一键回到起点继续下一个，还是层层返回

## 维度 4：设备适配 — "手机上用也一样好吗？"

**叛逃者**："我在 {竞品} 移动端操作很顺手，这里在手机上按钮能点到吗？"
**重度用户**："我大部分时间在手机上用，字太小、按钮点不准、老误触。"

- 移动端截图（375×812）→ 视觉模型分析
- 触控目标：所有按钮/链接实际尺寸 ≥ 44×44px
- 响应式断裂：窗口从宽拉到窄，布局是否在某一点断裂
- 字体大小：移动端 < 14px 记入
- 点击区域：相邻可点击元素间距是否足够，是否容易误触

## 维度 5：内容体验 — "内容专业吗？信息对劲吗？"

**叛逃者**："{竞品} 的信息组织得很清楚，这里内容有点乱，层级不清晰。"
**重度用户**："我每天都看这个页面的数据，但信息组织得不好，经常翻来覆去找。"

- 占位文字残留：DOM 扫描第 1 条结果并入本维度
- **lorem ipsum 残留**：未替换的占位文字
- **meta 标签**：title、description 是否存在且合理
- **favicon**：标签页是否有图标
- **标题层级**：h1 → h2 → h3 是否合理，是否跳级
- **链接文案**：是否用"点击这里"、"更多"等无意义文字
- **ARIA 标签**：有 role 的元素是否缺 aria-label/labelledby
- **信息密度**：过于拥挤或过于稀疏
- **数据一致性 / 文案一致性**：同一数据、同一概念（"姓名" vs "用户名"、"已完成" vs "done"）的叫法——**记录本页用词与值，跨页比对由主 agent 汇总时做**
- **数字/日期格式统一**：千分位、日期格式、相对时间（"1天前" vs "2024-01-01"）——同上，记录本页
- **数字单位**：时长/数量/金额类数字是否带单位（通话时长显示"32"应为"32秒"）
- **中文页英文残留**：DOM 扫描第 11 条结果并入本维度

## 维度 6：搜索与发现 — "我能找到我想找的东西吗？"

**叛逃者**："{竞品} 上搜什么有什么，筛选排序特别顺手，这里找东西好费劲。"
**重度用户**："我每天在这个页面找东西，但搜索不好用，筛选项也不够。"

- **搜索入口**：是否有搜索框，位置是否明显
- **搜索反馈**：实时出结果还是要点按钮？结果是否展示数量？
- **搜索容错**：输错字是否有纠错提示？无结果时是否有"换个关键词"引导？
- **筛选体系**：是否有筛选器（分类/价格/时间/状态），是否覆盖核心维度
- **排序能力**：是否支持时间/热度/价格/评分排序，方向可切换
- **导航结构**：主导航是否清晰，面包屑是否存在，用户是否知道"我在哪"
- **推荐与关联**：详情页是否有"相关推荐"、"猜你喜欢"
- **分页/加载更多**：超过一屏是否有分页，翻页后筛选条件是否保持

## 维度 7：功能完备性 — "该有的都有吗？"

**叛逃者**："{竞品} 这类页面标配的东西，这里少了一截？"
**重度用户**："我得绕路，就是缺个按钮。"

- **预期功能清单**（扫描本页前必列，来源三选：项目画像 / 业界惯例 / 项目文档），逐项核对存在性，缺一项记「功能缺失」，标注来源
- **默认值**：筛选默认、日期默认、排序默认是否合理（如筛选默认应含"全部"）
- **操作闭环**：列表项查看/编辑/删除是否齐全，缺一环记「功能缺失」
- **通用控件惯例**：分页器能跳页+改每页条数；日期选择器能直接弹出；搜索框有占位提示
- **应可点而不可点**：列表中的 ID/姓名/编号/标题类文本通常应是详情入口——对照同类页面惯例抽查是否可点，纯文本 = 记「缺入口」；台账只枚举已存在的元素，**"缺一个入口"只能靠这条发现**
- **跨组织数据隔离**：多组织/多校区项目，逐行核对列表数据的组织归属——A 组织页面混入 B 组织数据 = 记「数据隔离失效」P0
- **多系统互切**：项目含多个子系统时，互切往返 2 次，验证无状态残留、无 404、无"显示已是X但页面没变"
