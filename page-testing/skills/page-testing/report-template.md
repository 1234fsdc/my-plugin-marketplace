# report-template — 报告模板（主 agent 汇总时读）

## 写作规则

1. **只描述问题，不写修复方案**。每个问题写三件套：现状 → 影响 → 代码位置
2. 产品层面的功能建议与技术缺陷分章节并存，不算越界

## 严重度分级

| 级别 | 标签 | 定义 | 示例 |
|------|------|------|------|
| P0-紧急 | 🔴 | 功能不可用、数据错误、安全漏洞、白屏/崩溃 | 表单提交无响应、JS 报错、404/500、数据错乱 |
| P1-高 | 🟠 | 核心体验严重受损 | 视觉错乱、引导缺失导致用户卡住、操作步骤过多、性能严重慢 |
| P2-中 | 🟡 | 体验不佳但可绕过 | 对比度不足、响应式局部断裂、触控目标偏小、缺 meta 标签 |
| P3-低 | 🔵 | 细节优化、建议性改进 | 文案微调、间距微调、信息密度调整、动画过渡优化 |
