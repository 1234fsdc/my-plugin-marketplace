# fix-verify — 修复验收协议

适用：修复后的页面验收。只验证改动及其受影响面，不做全页重扫。

## 证据闸门

每个 PASS 必须附机器可读证据：DOM 值、API 响应字段、日志行或截图。没有证据只能标 `⚠️ 未验证`。

资源加载须用实际加载状态验证；同一资源在不同页面出现时逐页验证。主代理收到结果后随机复核 2-3 个 PASS 项；`ledger` 的 skipped 超过 20% 时重派或明确报告缺口。

## 验收内容

1. **版本**：核对页面加载的脚本、样式版本；不符则本轮无效。
2. **分层**：按改动层验证实际结果：
   - API/字段：响应字段值；
   - 渲染：DOM 文本和属性；
   - 交互：点击后的状态变化；
   - 布局：计算样式和改动区域截图。
3. **受影响面**：改动事件、接口、字段或推送时，检查所有前端消费点。
4. **异常**：生成内容为空或逻辑处于异常处理分支时，核对服务日志后再下结论。
5. **事件**：涉及流式/推送时，检查完整事件序列、重复事件、计数回退和中英字段混用。
6. **负样本**：文案和空态至少验证有值、无值两种形态；不支持输入应有明确边界反馈。
7. **视口**：涉及响应式、浮层或面板时，验证相关宽度与开关状态，并附改动区截图。

## 返回

在 `scan-protocol.md` 的标准格式之上，额外返回：

`版本断言`、`分层断言`、`日志审计`、`视口/状态矩阵`、`特写截图`。
